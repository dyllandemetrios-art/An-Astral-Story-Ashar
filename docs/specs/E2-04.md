# E2-04 — Système de vagues (WaveData)
**Semaine** : S2 (8–14 oct) · **Estimation** : 1 ½ j · **Dépend de** : E2-02 · **Références** : `CLAUDE.md`, `docs/CAHIER_DES_CHARGES.md` (§5.3, §6 WaveData, §7.5), `docs/backlog.csv`

> **Statut : spec rédigée par Claude Code à partir de la ligne du backlog et du §6, pendant que Dyllan dort (consigne du 27/09).** Backlog : « Spawn cadencé par timeline en secondes, lisible depuis la table de vagues ».

- **Périmètre** : le §6 prévoit sept types d'événements (`Spawn`, `Dialogue`, `Zone`, `WaitForClear`, `ScrollSpeed`, `Boss`, `End`). Cette story fait ceux qui se terminent proprement **sans dépendre de systèmes qui n'existent pas encore** : `Spawn`, `WaitForClear`, `ScrollSpeed` et `End`. `Dialogue` (E3-02), `Zone` (E4) et `Boss` (E5) s'ajouteront avec leurs stories, sans changer le reste.
- **À faire** :
  1. `WaveData` (ScriptableObject) : une liste ordonnée d'événements, chacun avec son temps en secondes, son type et ses réglages. Un `Spawn` a : ennemi (`EnemyData`), nombre, formation (`Single`, `Line`, `V`, `Column`), entrée (haut, gauche, droite, ou sur l'écran pour les ennemis fixes), décalage, espacement, délai entre unités, nom de groupe. Un `ScrollSpeed` a une vitesse cible et une durée. Le temps s'écoule **depuis le dernier `WaitForClear` terminé** (§6).
  2. `MissionRunnerController` : joue la table dans l'ordre, crée les ennemis avec le délai voulu, compte les ennemis de chaque groupe, attend un groupe pour `WaitForClear`, change la vitesse de défilement du décor en douceur, et annonce la fin (`GameEvents.OnMissionEnded`).
  3. Un groupe est « vide » quand aucun de ses ennemis n'est vivant **ni en attente d'apparaître** ; un ennemi qui sort de l'écran compte comme éliminé du groupe.
  4. Une table de test `WaveData_TestM1` qui couvre chaque type d'événement (§7.5 : « des WaveData de test qui couvrent chaque type d'événement »), et le contrôleur ajouté à `TestBed`.
- **Critères** :
  - [ ] Une vague se décrit entièrement dans un asset, lisible comme un tableau, sans code.
  - [ ] Les ennemis d'un groupe apparaissent aux positions et aux instants écrits dans la table.
  - [ ] `WaitForClear` arrête bien le temps du bloc et le relance à 0 quand le groupe a disparu.
  - [ ] Le changement de vitesse du décor est progressif et se termine exactement à la valeur voulue.
  - [ ] Une table dont les temps reculent dans un bloc est signalée dans la console.
- **Test** : dans `TestBed`, désactiver le générateur de test et l'émetteur de balles, puis démarrer la mission (menu de l'`MissionRunner`, « Start mission »).
- **Hors périmètre** : dialogues, zones de décor, boss, `MissionData` (missions M1 et M2 complètes), score et vies (E2-05), multiplicateurs de `GameBalanceData` (E2-06), écran de fin de mission.
- **Conventions** : celles de `CLAUDE.md` (commentaires anglais pédagogiques, `[Tooltip]`, dossiers par fonctionnalité, prefabs, scène rangée). Elles font partie des critères d'acceptation.

## Compte rendu (rempli par Claude Code, en français)

**Branche** : `story/E2-04-waves`, créée à partir de `story/E2-03-fire-patterns`.

- **Fichiers modifiés** :
  - `Features/Waves/Scripts/` : `WaveData.cs` (table, événements et énumérations ; contrôle de l'ordre des temps signalé dans la console), `WaveMath.cs` (calculs purs : position de chaque ennemi d'un groupe selon l'entrée et la formation, courbe de la vitesse de défilement), `MissionRunnerController.cs` (la timeline).
  - Prefab `Features/Waves/Prefabs/MissionRunner.prefab`, table `Features/Waves/Data/WaveData_TestM1.asset` (11 événements, trois blocs), instance dans `TestBed` sous `--- SYSTEMS ---` avec **Auto Start décoché**.
  - Petits ajouts aux classes existantes : `EnemyController.Removed` (événement levé quand un ennemi disparaît, tué ou non, pour compter les groupes), `BackgroundScrollController.BaseSpeed` (la vitesse peut être changée par la mission), `GameEvents.OnMissionEnded`.
  - Tests : `WaveTests.cs` (12 cas : entrées haut, gauche, droite et écran, ligne, V, colonne, ordre des temps avec et sans `WaitForClear`, courbe de vitesse). Total : 114 tests, tous verts.
- **Formations** : `Line` étale le groupe le long du bord d'entrée ; `V` fait de même et recule les ennemis extérieurs de 0,6 × l'espacement, si bien que celui du milieu ouvre la marche ; `Column` garde tous les ennemis au même point (c'est le délai entre unités qui les sépare) ; `Single` pour un seul.
- **Table de test `WaveData_TestM1`** : bloc 1 : 5 drones en V (0,25 s entre chacun), accélération du décor à 7 u/s, 3 drones en piqué en ligne, 3 chasseurs entrant par la gauche, puis attente du groupe « fighters » ; bloc 2 : décor à 2 u/s, deux tourelles fixes sur l'écran (spirale et tir télégraphié), attente du groupe « turrets » (à toi de les détruire) ; bloc 3 : décor à 4 u/s, fin de mission 3 s plus tard.
- **Comment tester en 2 minutes** :
  1. Ouvre `TestBed`. Sélectionne `DebugEnemySpawner` et `DebugBulletEmitter` et **décoche-les** (ils gêneraient). Lance le Play.
  2. Sélectionne `--- SYSTEMS --- > MissionRunner`, clique sur les trois points de son composant `Mission Runner Controller` puis **Start mission**. Tu vois la mission se dérouler : les statuts, le temps du bloc et le nombre d'ennemis vivants sont lisibles sous `Debug`.
  3. Tire avec **J** ou **W** : détruis les deux tourelles quand elles apparaissent ; la mission continue et se termine (`Finished`).
  4. Ouvre `WaveData_TestM1` et modifie un temps, un nombre ou une formation : tu relis la table comme un tableau et le changement se voit à la mission suivante.
  - Déjà vérifié de mon côté (Play Mode, temps ×4 image par image) : 5 drones créés à 0,25 s d'écart ; le décor passe de 4 à 7 u/s progressivement ; l'attente du groupe « fighters » se termine quand les chasseurs quittent l'écran (le temps du bloc repart à 0) ; les tourelles apparaissent sur l'écran, la mission attend, puis **après leur destruction** : bloc suivant, vitesse ramenée à 4 u/s en douceur, `End` atteint à 3 s, l'événement de fin est levé **une seule fois** ; console propre.
- **Limites connues et choix à valider** :
  - Un seul type d'entrée, un seul groupe de réglages par événement : la table est un tableau simple, pas un éditeur graphique (l'Inspector de `WaveData` affiche la liste des événements, avec les réglages de tous les types ; seuls ceux de son type sont lus). Un affichage plus lisible (masquer les champs inutiles) est possible en polish.
  - **Les ennemis créés par la table ne tiennent pas encore compte des multiplicateurs globaux** (PV, densité de tir) : E2-06.
  - Tant que les tourelles ne sont pas détruites, la mission attend indéfiniment : c'est voulu (« les trois verrous à détruire » du §7.5).
  - La zone de vie des ennemis est l'écran agrandi de 5 u, celle des balles de 1 u (réglables sur le contrôleur).
  - `Dialogue`, `Zone` et `Boss` sont absents de l'énumération : ils seront ajoutés avec leurs stories (une valeur d'énumération sans comportement serait une valeur morte).
- **Placeholders créés** : aucun.
- **Idées notées** : la table de test pourra devenir le modèle de `WaveData_M1` (P0-08 doit fournir la chronologie réelle).
