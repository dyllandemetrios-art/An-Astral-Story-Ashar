# E1-05 — Limites, collisions et hitbox lisible
**Semaine** : S1 (1–7 oct) · **Estimation** : 0,5 ½ j · **Dépend de** : E1-02 · **Références** : `CLAUDE.md`, `docs/CAHIER_DES_CHARGES.md`

- **Fichiers** : `Features/Player/Scripts/PlayerHealthController.cs`, `Core/Scripts/Layers.cs`, `Core/Scripts/GameEvents.cs` (premier événement : `OnPlayerHit`), prefabs `Features/Combat/Prefabs/EnemyBulletDummy` et `DebugBulletEmitter` (placés uniquement dans `TestBed`).
- **À faire** : couches et matrice de collisions du §5.4 ; hitbox circulaire de `hitboxRadius` avec un point argent (option `showHitbox`) ; un projectile ennemi factice qui touche la hitbox déclenche `GameEvents.OnPlayerHit` (flash), sauf si `IsInvulnerable`.
- **Critères** : un projectile qui frôle le sprite sans toucher la hitbox ne déclenche rien ; le point de hitbox se masque via le ScriptableObject.
- **Test** : dans `TestBed`, un émetteur factice tire sur le joueur ; vérifier les frôlements et les impacts.
- **Conventions** : celles de `CLAUDE.md` (commentaires anglais pédagogiques, `[Tooltip]`, dossiers par fonctionnalité, prefabs, scène rangée). Elles font partie des critères d'acceptation.

- **Comment tester en 2 minutes** :
  1. Ouvre `TestBed`, lance le Play. Un point argent bordé de bleu foncé apparaît au centre du vaisseau ; l'émetteur de test lâche une balle orange toutes les 0,6 s, alignée sur le vaisseau avec un décalage qui change (0, 0,35, -0,35, 0,2, -0,2).
  2. Reste immobile : **seules les balles à 0 te touchent** (1 balle sur 5). Les autres frôlent le sprite sans rien déclencher.
  3. Sélectionne `PlayerShip` : sous `Debug` du `PlayerHealthController`, `Hit Count` augmente à chaque impact. Fais un dash (M / V / RT) juste avant une balle : pendant l'invulnérabilité, elle traverse le vaisseau et le compteur ne bouge pas.
  4. Dans `PlayerShipData_Default`, décoche `Show Hitbox` : le point disparaît. Change `Hitbox Radius` : la zone de contact suit en direct.
  - Déjà vérifié de mon côté (Play Mode, image par image) : sur 9 balles tirées, 2 impacts (les balles à 0, aux bons moments) et 2 événements `OnPlayerHit`, les balles à ±0,2 et ±0,35 sont passées sans impact ; vaisseau invulnérable : 0 impact sur 4 s avec plusieurs balles visées ; point masqué et affiché par la donnée ; rayon 0,5 appliqué puis 0,11 restauré ; capture : point visible, balles ennemies orange bien distinctes des balles argent.
- **Limites connues** :
  - **Le flash du vaisseau touché n'est pas fait** : c'est le rôle de E1-06 (retour visuel). L'événement `OnPlayerHit` est prêt à être écouté. Pour l'instant, un impact détruit la balle, incrémente `Hit Count` et rien d'autre : pas de vie perdue, pas de réapparition.
  - Les collisions balle du joueur / ennemi ne sont définies que dans la matrice : la `PlayerBullet` n'a pas encore de collider (E2). Idem pour les corps d'ennemis et les power-ups.
  - La zone de graze (couche `PlayerGraze`) existe dans la matrice mais son collider arrive avec E1-09.
  - Le rayon de la hitbox est appliqué à chaque image (pas seulement au démarrage) pour que tu puisses le régler en jouant ; le coût est négligeable.
  - Le point de hitbox est toujours visible tant que `Show Hitbox` est coché : l'option dans les menus du jeu viendra avec le menu Options.
- **Placeholders créés** : aucun (le point de hitbox est un asset définitif ; la balle ennemie factice est un outil de test).
- **Idées notées** : bulles de cooldown dans le HUD (idée de Dyllan), dans `docs/notes/idees.md`.
